# P0 数据协议与复核规范

## 共同业务

RepoMentor Python 是仓库学习环境；未来 RepoMentor-Mini 的训练样本来自同一环境，训练后的模型回接同一回答与工具接口。两者共享 `snapshot_id`、commit SHA、相对路径、引用行号、任务类别和固定评测集。

任务分类：仓库概览、入口/控制流、跨文件依赖、测试关联、对话追问、信息不足与澄清、受控工具决策。P0 的 60 条种子集中验证代码解释和边界行为，不能代表这些类别的完整覆盖；P4/P6 扩充跨文件、多轮和工具任务，P10 再做完整业务评测。

## 仓库与版本

`experiments/p0/corpus.json` 冻结 20 个公开仓库：训练 12、验证 4、测试 4，各集合的 Python / JS/TS 各半。先划分再生产任务。两份 sindresorhus 异步库属于同一 family，均放训练集；所有仓库的 GitHub fork 标志与上游许可文件均已保存。

`NOASSERTION` 不直接当作无许可证：根据固定提交的许可正文，记录 packaging、boltons、dateutil、outcome 的许可组合/继承情况。只保存许可证来源与哈希，不以此声称完成专业法律审核。后续导出样本必须保留原作者、文件来源、许可证和必要声明。

代码不从可变化的 checkout 读取。Git commit、tree 和 blob 固定后，工作目录新增文件、修改分支、symlink、submodule 都不能改变已有快照看到的源码。

## 重复与污染控制

去重扫描使用规范化 token 的 20-token shingles；至少 80 tokens 的源码文件才参与，跨集合 containment ≥0.8 则双方文件进入排除清单。扫描了 1,159 个文件，本轮没有达到该阈值的跨集合近重复对。保留扫描方法及 `exclusions` 字段，后续采样必须检查它。

这项检测不覆盖所有短片段、语义改写或模型预训练污染。源码内已有归属声明也须保留，例如 more-itertools 的 recipes 来自 Python itertools 文档，nanoid 注明字符串池优化来源。不能把公开 GitHub 仓库描述成模型从未见过的私有测试集。

测试仓库本轮只做版本、许可、manifest 与去重处理，不创建任务、答案、训练轨迹或模型报告。验证仓库允许开发调试；旧 8 仓库报告回归与训练/验证/测试清单完全分开。

## 种子任务格式

每题包含任务 ID、仓库、SHA、输入问题、历史、gold 必要事实、可接受来源及源码片段哈希。输入与 gold 分开存储，运行时只接收 `input`，不得把标准答案、评分项或奖励字段喂给待测模型。

目前 60 题由 Codex 逐条阅读固定源码后编写，并检查行号/片段哈希：`source_reviewed=true`，`human_approved=false`。这些是可复核开发种子，不冒充独立人工标注，更不是已经完成的最终盲测集。主计划的“60 条人工核验”验收仍需人审签核。

人工复核时逐题检查：问题无歧义；必要事实正确且完整；引用范围覆盖支持事实；负例未把“未看到”写成“绝不存在”；回答没有要求未提供的运行时信息。复核人、时间、改动与判定另外记录，不能只批量把标志设为 true。

## 评分规则

事实正确、关键点覆盖、引用支持、信息不足处理分别计分；路径存在只说明引用合法，不能自动判定其支持结论。支持多种正确表述和可替代来源，避免仅靠标准答案子串匹配。

人工签核后冻结数据版本。模型 judge 只作辅助，与人审样本校准。报告结构、工具执行成功、文件召回率、回答正确率和任务成功率分别报告。

旧 `eval/agentic-benchmark.json` 保持原样，Python 使用独立 `legacy-regression.json`。

- Vite：将测试目录替换为具体的 `dev.spec.ts`。
- MCP TS SDK：更新到当前 monorepo 的 packages 路径。
- Claude TS SDK：该公开仓库含文档和 session-store 示例，没有假设的 SDK `src/query.ts`；参考路径明确覆盖现有 Postgres 示例，不能解释成 SDK 内部实现。

所有修改保留原始 gold、路径存在性审计和原因。新结果不用于声称相对错误旧 gold 的召回提升。
