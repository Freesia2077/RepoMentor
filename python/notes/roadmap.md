# 两个项目的共同路线图

业务统一为“理解一个陌生代码仓库并完成学习问答”：项目一研究如何检索、调用工具、管理上下文并可靠回答；项目二研究后训练能否改善同一环境下的小模型行为。Python 是共同工程与评测入口。

| 阶段 | 工作 | 验收重点 |
| --- | --- | --- |
| P0 | 冻结仓库、版本、划分和任务种子 | 技术准备已完成；60 条验证种子的人审仍待签核 |
| P1 | Python contracts、Git snapshots、工具、Harness、轨迹 | 已实现；独立离线测试和可安装包 |
| P2 | 官方 Python Claude SDK、CLI 三阶段报告 | 已实现；真实调用和报告留档，保留错误案例 |
| P3 | 本地 Qwen3.5-4B 接入、通用模型运行时、实验入口 | 实测显存、速度、上下文上限、工具协议；同一任务可替换 runtime |
| P4 | 持续对话与普通 RAG | 明确问题/历史/检索/回答接口，建立无检索与普通 RAG 基线 |
| P5 | 代码切块、混合检索、重排、上下文管理 | 固定模型比较检索命中、引用覆盖、正确率、延迟与成本 |
| P6 | Agentic RAG 与可复用工具环境 | 调查、重查、停止、拒答；检验是否优于固定检索，记录失败轨迹 |
| P7 | RepoMentor-Mini 数据与 MiniMind SFT | 只用训练划分；记录过滤、损失、模板、推理和固定验证指标 |
| P8 | 同任务偏好对与 DPO | 正误/引用/拒答/工具效率的偏好要有依据，与 SFT 直接对照 |
| P9 | 小规模真实工具环境 GRPO | 仅在可验证奖励与稳定基线成立时做；审计奖励投机，不为名词增加阶段 |
| P10 | 正式模型与系统对比、演示、面试材料 | 一次性使用封存测试；汇总消融、成本、失败、可复现命令 |

MiniMind 后训练前后对比用于分析训练收益；Qwen3.5-4B 是更强参考模型，不把不同参数规模和预训练资源的差异归因于后训练算法。固定工具、任务、数据划分和 token 预算比较模型；固定模型比较 RAG / Agent 策略。量化方式、上下文、提示词、重试和服务版本必须留档。

当前只交付 P0–P2。本次复查和发布不启动新模型调用、权重下载、训练、对话或检索实现。完整的本地规划文档另保存在仓库工作区 `docs/repomentor-python-and-minimind-plan.md`（该目录按原仓库规则不提交）。
