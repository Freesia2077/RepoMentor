## 第二项目：RepoAlign——面向研发知识助手的小模型证据对齐后训练

**2026-11-04方案，尚未下载新权重、租GPU或开始训练。** 目标是一周完成一条可复核的SFT→DPO路线，短租单卡；下文样本数、配置、工时和预算均为计划，效果尚未产生。

### 定位与项目故事

业务面向开发者学习、接手开源仓库，重点回答函数行为、参数条件、模块关系及测试含义。部署目标是用较小模型承接有源码上下文的常见问答，评估回答质量与推理开销的取舍，不预设它可以替代9B。

两个项目共享业务与基础设施，贡献分别为：RepoMentor研究如何找到并管理源码；RepoAlign固定可见证据，研究如何通过数据和后训练改善模型的证据利用。复用来源协议、选源和评测记录，不再搭第二套RAG或Agent循环。

叙事顺序：开发者需要理解仓库 → 检索命中后仍有条件误读、相似函数混用和无据断言 → 用公开监督冷启，再从错误回答构建偏好 → 在相同输入下比较训练前后，检查业务迁移与成本。既有RAG失败只能提供问题分类；其50道题和原回答均不进入训练。

创新重点是“真实失败驱动的数据设计与验证”，不宣称发明SFT/DPO算法。[RAFT](https://gorilla.cs.berkeley.edu/blogs/9_raft.html)已有正确证据与干扰文档混合训练；[SWE-QA-Pro](https://github.com/TIGER-AI-Lab/SWE-QA-Pro/blob/main/train/README.md)已有仓库轨迹SFT和GRPO。我们的可验证差异是短上下文小模型、同证据偏好、源码条件错误切片与单卡预算。

### 模型与框架：只训练一个规模

主选[Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B)，预检显存或吞吐不合适时改为[2B](https://huggingface.co/Qwen/Qwen3.5-2B)，随后全流程固定该规模。RAG原9B不参与训练；不同规模旧成绩不能证明本轮训练收益。

训练选PyTorch＋Transformers＋Datasets＋PEFT＋TRL，直接复用SFTTrainer/DPOTrainer；Unsloth仅在需要时作为同一训练路线的加速后端。LlamaFactory/ms-swift可作为现成配置参考，不同时维护多套训练入口。新增逻辑限于数据转换、偏好筛选和结果整理。

优先单张24GB GPU、BF16 LoRA。Unsloth当前[Qwen3.5训练指南](https://unsloth.ai/docs/models/qwen3.5/fine-tune)列有4B BF16 LoRA实例，同时明确不建议该系列4-bit QLoRA；这不能当作本项目长度和DPO显存的保证。首轮不加载视觉输入、不训练视觉塔。Transformers是库名，Qwen3.5本身采用线性注意力与标准注意力混合结构，不能混称纯标准Transformer。

本地仍使用D:\anaconda\envs\repomentor\python.exe -s，不更换或安装另一套本地环境。训练拟在租卡方Linux镜像运行；启动前锁定模型revision、镜像与依赖版本，不覆盖现有RAG环境。

| 数据 | 公开规模与定位 | 首轮使用计划 |

| [SWE-QA-Pro SFT](https://huggingface.co/datasets/TIGER-Lab/SWE-QA-Pro-SFT-Trajectories) | 1,000条教师合成的多轮仓库轨迹，不是十万条代码问答 | 准入后争取保留约400–800条回答节点，补充仓库适配；另留开发题，不增加教师长轨迹生成 |
| [SWE-QA-Pro Bench](https://huggingface.co/datasets/TIGER-Lab/SWE-QA-Pro-Bench) | 26仓库、260题 | 先排重及隔离训练仓库，再固定最多5库×10题做业务评测；不足时如实报告有效题数 |
| [RAGBench](https://huggingface.co/datasets/galileo-ai/ragbench) | 约100k、12个子集，有技术支持等场景 | 扩展候选，首周不同时引入；其生成回答不天然都是正确SFT标签 |

HotpotQA解决便宜训练、自动评分与数据规模问题，但属于通用多跳问答，不能把它的增益写成代码理解增益。SWE-QA-Pro负责验证仓库迁移。公开数据总量、实际有效训练量、增强版本数分别报告；同一轨迹切片不扩大独立问题数。记录原许可与署名要求，派生材料保留来源。

已有[SWE数据预检元数据](../artifacts/public-data-audit-2026-11-03/metadata.json)只覆盖2026-11-03的版本、规模和一条轨迹。该轨迹工具角色为tool_call/tool_response，约6.9万消息字符，且无显式repo/commit字段。不能直接作为当前SDK训练记录导入，也不能用一条推断全量长度分布。

数据准入沿用[数据协议](data-protocol.md)：先按来源问题/仓库分组划分，再增强和生成候选；进行规范化题干及可复用的源码近重复检查。跨HotpotQA与其他聚合数据查原始ID；不混用HotpotQA的distractor/fullwiki重复样本。RAG旧50题、开发失败题、原四个封存最终测试仓库及其衍生内容排除出训练。公开问答可能已被基座预训练使用，本次划分不能证明没有预训练污染；EM/F1增益也不能单独证明模型依赖了证据。

仓库训练样本必须恢复来源身份与实际工具观察，输入只能来自回答前已可见的源码，不能从参考答案反向拼“证据”。优先提取问题＋必要工具原文→最终回答，审核源码是否支持教师回答；来源不明、证据缺失或关键内容超长的记录按规则排除。只训练回答节点，不宣称训练了工具规划或多轮Agent策略。

第1天给仓库轨迹准入最多半天：如可追溯子集不足，就先交付公开证据问答的SFT/DPO，并保留仓库外域测试；此时项目表述为“证据问答后训练及仓库迁移评测”，不能声称已完成仓库数据适配。不能为凑数量放宽身份或划分规则。

### SFT→DPO具体怎么做

SFT统一使用问题、带来源编号的真实上下文和回答。HotpotQA利用原答案、支持句构造短回答及依据；代码部分沿用审核后的教师最终回答和原文。既有教师输出可称离线响应蒸馏，不称在线蒸馏OPD，也不额外生成大量长思维链。

采用prompt-completion格式，仅回答token计算loss，问题/源码/padding均mask；用实际token解码检查mask、EOS和chat template，不能只看训练loss下降。TRL的[完成部分loss说明](https://huggingface.co/docs/trl/sft_trainer)可直接复用。对少量训练样本增加相似但不适用的真实源码，保留正确证据并匹配总长度；不改写原始源码来冒充真实仓库版本。

DPO从SFT模型对训练分区问题产生的少量候选中挖错误，目标筛出约300–600对，样本少但标签可靠优先。每对必须具有完全相同的问题和可见证据；chosen有可核验支持，rejected是可确证的实体/分支错误、遗漏决定性条件或无依据断言。模板造错可补充，不能全部依赖随机换名字或“长答案胜短答案”。

HotpotQA用官方答案规范化及支持句辅助筛选，但EM为0不必然错误，需排除别名、等价表达与其他有效证据。代码候选以源码事实审核，判断不清的对直接丢弃；教师答案不自动胜出。抽查约50对，记录错误类型、长度差和筛除率；若代码对不足，DPO可只用通用证据对，单独解释迁移限制。

DPO以SFT检查点为初始化及冻结参考，不能因关闭LoRA而误把参考退回原始基座。优先缓存该检查点的reference log-prob，缓存绑定tokenizer、模板和截断方式，复用[TRL DPOTrainer](https://huggingface.co/docs/trl/dpo_trainer)，不实现自定义优化器或RL循环。训练reward margin上升只是诊断，独立生成评测决定是否保留DPO。

| 起始配置 | 计划值与约束 |
| --- | --- |
| 长度/批量 | 总序列上限4,096 token（含回答），micro batch 1、梯度累积16；先留出回答预算，拒绝把关键证据截掉的训练样本 |
| LoRA | r=16、alpha=32、dropout=0.05；只选择语言侧实际线性模块，冻结视觉、词嵌入和输出头 |
| SFT | learning rate 1e-4，先1 epoch；梯度检查点、BF16、梯度裁剪 |
| DPO | learning rate 5e-6、beta=0.1，先1 epoch；预计算参考概率，单批显存与参考身份须实测 |
| 预检 | 20–50步检查loss/梯度/显存/有效token/s，少量样本过拟合验证mask与加载；预检归开发，不计最终效果 |

这些是起点，不做大范围调参。数据配比、模板和证据长度在比较前固定；SFT缺乏业务收益时先查输入与标签，不靠追加PO算法掩盖问题。

### 最小评测与保留规则

| 条件 | 比较目的 |
| --- | --- |
| 同一原始4B/2B＋同一证据 | 训练前基线 |
| SFT＋同一证据 | 监督训练的增量 |
| SFT→DPO＋同一证据 | 这批偏好与DPO流程的增量 |

模型、tokenizer、量化精度、提示、解码、输入原文和生成预算一致；首轮统一非思考模式。仅开发集选检查点，正式集一次性生成并留原始失败。主表只三组；不同时对比模型尺寸、多个PO算法或检索配置。

HotpotQA先冻结300题，使用[官方评价脚本](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py)报告答案EM/F1、支持句F1和joint指标；生成来源编号映射回原title/sentence索引。输入是给定distractor上下文，不是fullwiki检索成绩。按预先长度规则选取子集并报告覆盖率，不用gold挑“模型更容易答对”的输入；官方validation子集不能写成官方隐藏test成绩。

仓库题复用现有混合检索，固定官方仓库快照并冻结每题初始源码，三模型各一次作答；这是SWE-QA-Pro题目的自定义单次RAG对照，不是其原多轮Agent设置的完整复现。检索不到必要源码与读到后答错分开分析。沿用官方量表/参考的模型辅助评分，输出少量来源核对案例，说明评审模型、预算与分母；不把行号合法或格式成功当事实正确。

另外从未进入训练的题生成少量干扰输入，保持正确证据及总预算，检查条件误读、相似源码混用、无据断言；干净集与干扰切片单独报。首周不追加一整套证据缺失/拒答训练，以免奖励模型一律拒答。

保留标准在正式生成前写入实验配置：独立集正确性有可解释增量，来源支持、回答覆盖率和输出长度没有明显恶化；同时报告配对变化与不确定性，300题/50题不足以证明通用领先。三组只支持“该训练流程有增益”；若要声称DPO优于多看一遍正确答案，才追加同chosen、匹配更新预算的继续SFT对照，不能省略后作因果宣传。

如DPO无收益，保留负结果，部署最佳SFT，不重跑正式集挑最好分数。目标是一个有训练证据、有业务分析的项目，不预设提升百分比。

### 热点覆盖与实际范围

| 技术 | 在本项目的位置 |
| --- | --- |
| Transformers / PyTorch / PEFT / LoRA / TRL | 实际训练主栈；说明冻结参数、显存构成和loss mask |
| SFT / 离线蒸馏 / 拒绝采样 / Hard Negative / DPO | 实际数据与训练主线；区分筛数据与优化算法 |
| QLoRA | 理解量化＋适配器机制；因Qwen3.5当前建议，不列为默认已实现 |
| [SimPO](https://github.com/princeton-nlp/SimPO)、[ORPO](https://arxiv.org/abs/2403.07691) | 可讨论无参考模型偏好目标的取舍，首周不另训；ORPO不是简单把DPO去掉reference |
| [GRPO](https://huggingface.co/docs/trl/grpo_trainer)、PPO / RLVR | 在线采样与奖励优化的后续路线；代码问答没有天然可靠的免费可验证奖励，引用合法不够充当语义奖励 |
| [DAPO](https://arxiv.org/abs/2503.14476)、[GSPO](https://arxiv.org/abs/2507.18071) | 理解采样/裁剪、长度偏差、token与序列重要性比率；一个Trainer配置不等于完整复现原论文系统 |
| OPD / vLLM / verl / DeepSpeed | 在线蒸馏、推理和分布式训练扩展；首周不搭该组合，不把了解写成实战 |

需要强化学习实操时，在主结果完成后另立短答案、可核验奖励的GRPO小实验；不能把另一任务的reward曲线包装成仓库Agent能力提升。首周不把它设成必交项。

### 一周安排与预算

| 天 | 交付 |
| --- | --- |
| 1 | 来源/许可/长度与仓库身份准入，确定可用分区，冻结开发与正式ID；不租卡等数据清洗 |
| 2 | 转换短上下文样本，人工核对少量标签；租卡后完成模型/模板/LoRA/mask与20–50步资源预检 |
| 3 | 1次SFT，开发集检查；依据实测吞吐缩减训练规模，不调正式集 |
| 4 | SFT模型生成偏好候选，筛300–600对，检查长度和事实标签 |
| 5 | 1次DPO，开发集判断是否保留；缓存SFT参考概率并核对参考身份 |
| 6 | 冻结三组评测与少量干扰切片，记录质量、显存、生成token/时延及账单 |
| 7 | 整理少量代表性成功/失败、训练配置及结论；第二项目材料完成后再合并准备面试 |

GPU目标控制在约12–24计费小时，须由第2天实测token/s修正，不是训练时长承诺。按“24小时×假设3元/时=72元”预算示例，加数据筛选/评审与存储重试，首轮计划控制在100–200元。实际卡价、镜像可用性与存储费用以租用页为准，[AutoDL计费说明](https://www.autodl.com/docs/price/)仅支持计费规则；此处3元不是实时挂牌报价。不租整周，不训练时关机，检查持久存储计费。

租卡前准备数据与配置；单次长预检不通过先降为2B或缩小训练集，正式比较前重新固定条件。优先省去额外轨迹生成、在线奖励模型和反复评审，不只计算LoRA训练成本。

### 完成后如何包装

建议项目标题：“RepoAlign：面向研发知识助手的Qwen小模型后训练”。讲述核心是“把已检索到的证据用对，并在低预算下验证”，不以复现MiniMind或Search-R1作为项目身份。公开训练数据和上游Trainer是基础，个人贡献落在来源审核、错误类型设计、偏好构建、训练排错与同条件评测。

简历结构预留四条：业务目标与模型 → 数据与难负例 → SFT/DPO及单卡优化 → 独立评测和质量/成本取舍。数字只填实测的有效样本、EM/F1、仓库评分、峰值显存、GPU时与成本；没有线上使用就不写线上收益。若仓库适配未通过准入或无迁移增益，按实际缩小标题与结论。

完成交付为数据来源及划分清单、少量上游训练配置/转换入口、LoRA身份和训练曲线、三组原始评测、成本记录及一份结论。新材料继续汇总在现有计划和实验索引，避免额外创建多份路线图。下一步执行从第1天的数据准入开始，本轮不自动训练。
