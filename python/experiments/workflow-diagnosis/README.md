## 用户和完成标准

用户是新接手 Python SDK/服务仓库的开发者，从具体行为或配置疑问开始阅读固定版本的源码。既有 JS/TS 检索继续保留，语言结果分别报告。

| 工作流 | 用户目标 | 交付和判定 |
| --- | --- | --- |
| 行为与配置解释 | 明确显式参数、默认值和条件分支怎样决定结果 | 直接结论、必要条件和源码依据；严重事实错误即失败 |
| 跨文件机制与测试定位 | 找到调用处、实际实现和相关测试断言 | 给出可核验阅读路径；明确未读部分，读取测试不当作执行测试 |
| 连续追问 | 修改条件或切换入口后继续解释 | 以当前问题为目标，更新入口、符号和证据；不复述过时结论 |

私有运行状态或源码不足题单列：指出缺少的信息，正文与 `insufficient_evidence` 一致。完整报告为辅助产物。
