# RepoMentor 面试演示提纲

用 5–8 分钟说明“仓库代码如何进入答案、哪些失败能被系统发现、Agent 何时值得增加成本”。完整统计见 [收尾报告](report.md)。

1. **业务与边界**：导入固定 Git SHA，通过学习问答、追问和阅读路径理解陌生仓库。Python 独立运行；只读目标代码，不执行其安装/测试命令。
2. **系统主线**：语法切块和符号索引 → 关键词/向量/重排与一跳候选 → SDK 按需工具 → 调用前上下文整理 → 可追溯答案。固定 RAG 作为相同初始来源的对照。
3. **正确案例**：展示 [跨函数 nth_or_last](markdown/confirmation-close-confirm-07--fixed.md)，检查 last 的真实分支；再展示 [JSONProvider.load](markdown/confirmation-close-confirm-09--sdk.md) 的动态分派。
4. **工具案例及限制**：展示 [Flask 补读](markdown/confirmation-close-confirm-10--sdk.md)。实际读取了关键源码，但最终回答仍遗漏条件，不能只用工具命中率说明质量提高。
5. **连续对话**：按顺序展示 CPU 演示四轮。第 1、4 轮可解释正确行为，第 2 轮引用不充分，第 3 轮错把清空列表说成删除键；不把它包装成全程正确演示。
6. **评测结论**：新确认固定 5/12、SDK 4/12，平均请求 1.00 / 2.08；SDK 结论正确更多，但严格解决率更低。额外成本多数用于研究和格式整理，实际使用工具仅一题，未证明整体 Agent 收益。
7. **工程可信性**：展示请求上限、失败留档、实际可见来源与历史来源的区别、零调用回放，以及“行号合法但不支持结论”的失败。
8. **两个项目的关联**：RepoMentor 提供仓库任务、工具、来源和评测；MiniMind 后续研究条件理解、完整输出和引用行为能否通过后训练改善。评测轨迹不进训练集，训练候选另从训练仓库生产并核验。

可以陈述的贡献：实现了有界的代码 RAG/SDK 助手和分层可复现评测，修复了长函数命中、续读和上下文可见性问题，并用负结果约束复杂度。

当前不可陈述的贡献：Agent 显著提高整体准确率、稳定完整正确报告、多专家质量收益、陌生仓库泛化、人工盲评通过、MiniMind 已完成训练。
