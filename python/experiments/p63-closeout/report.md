# RAG 收尾：实现冻结与质量边界

2026-10-19。当前 Python 主线完成工程、评测和演示交付，作为可复现的仓库学习助手原型封存。**端到端质量目标未通过，不宣称 SDK Agent 优于固定 RAG。** 本轮结束功能扩展；MiniMind 数据生产与训练尚未开始。

## 本轮交付

- 固定 RAG / SDK 共享符号、检索与一跳静态被调函数候选；路径排除在候选选择前生效，不把动态调用包装为已解析关系。
- SDK 初始、工具及压缩后的源码均有可核验行号；导航位置不等于已读证据。Agent 循环继续完全交给 SDK Runner。
- 报告独立研究/整理提示，最多 12,000 字节的入口、配置、文档与测试原文起点；区分文件清单和阅读缺口。显式证据行号越界或不在最终输入时由输出护栏阻止发布，原始失败仍保存。
- 保留有核验来源时的一次预留整理，不使用截断草稿；默认 Qwen 16K，最终输出上限 1,536，研究上限 1,024。
- `inspect-run` 可把已有问答或完整/部分报告导出 Markdown，明确失败与语义审核边界。

静态召回、提示和源码呈现一并改变，本轮不能归因哪一项带来多少质量收益；没有用确认题再选配置。

## 新确认结果

新建 **12 题、六个开发仓库各两题**，源码核对及题目在生成前冻结，配置见 [selection.json](selection.json)。这是为控制调用规模的小型同仓库确认，不是原 24 题复测、原定 24 题的等规模替代或陌生仓库泛化测试。新确认不含单独的信息不足题和测试断言题，这两类在开发诊断、对话中覆盖，结果不能混成同一总体准确率。

| 有效生成流程完成 | 10 | 12 |

“解决”要求流程成功、事实正确、内容充分、引用支持且不矛盾。SDK 的正确性分项较好，但引用和完整性仍限制解决率。SDK 25 次请求中，13 次研究、12 次整理；不能把额外请求全部解释为工具推理收益。

SDK 新解决 2 题、退步 3 题，净增 −1。其中一项新增解决来自固定版本地服务失败；只看双方均完成生成的题，新增 1、退步 3。五道跨函数题中固定解决 3、SDK 解决 2，净增 −1。平均请求数目标满足，整体不差和跨函数净增两题目标均未满足。

两个固定回答遇到本地 5xx，服务日志记录 `CUDA error: shared object initialization failed`。失败保留、不重试，纳入分母；不能将它们归因为模型语义错误。原 24 题固定 / SDK 各 8/24 的结果保持原样，新旧题不同，不能据 5/12 与 8/24 声称跨版本准确率变化。

## 失败与面试中应解释的取舍

- **来源可见仍解释错误**：CPU 第三轮把 `all.set(type, [])` 解释成删除键；这是理解错误，检索命中和引用范围合法都无法证明答案正确。
- **补查成功仍未完成回答**：Flask 的第 10 题 SDK 实际补读到换行拼接，但正文只概括 compact/debug，没有回答具体 indent/separators 条件。
- **引用遗漏关键条件**：例如只引用负数异常行，却同时给出 `random(0)` 的返回值；结论正确仍不满足引用支持。
- **报告推断越过已读范围**：把已有测试当作待补测试，将 `mock_datetime` 替换 Python 类说成修改系统时钟，或给出不可执行的 `.unit(unit)` 链式示例。
- **部署故障与语义失败分开**：混合 CUDA 检索涉及生成模型卸载重载，本机出现初始化失败。普通演示采用默认 BM25/CPU，先展示保存结果；此观察不证明故障唯一原因。
- **工具选择依赖后端**：两次诊断中本地后端没有遵守强制工具选择参数，默认没有启用这一保证。SDK 可提供工具选择控制，但本地兼容性仍须单独核验。[官方工具选择说明](https://developers.openai.com/api/docs/guides/function-calling)

因此，本项目可展示检索、工具、上下文、预算和评测的工程闭环；不能写成“高准确率生产助手”或“Agent 显著提高整体质量”。下一项目重点先验证完整作答、条件理解与引用对齐能否通过后训练改善，而不是继续堆检索模块。

## 成本、评审与复核

本轮 **82 次本地请求**：开发 20、工具选择诊断 4、新确认 37、报告 12、失败对话 1、CPU 对话 8；累计 **382/600**，付费 / DeepSeek **0**。没有继续 8K/16K 对照，没有反复重生成失败题。

49 个实际输出全部由 Codex 阅读源码并非盲评审，不是人工签核或官方榜单，全部 training_eligible=false。[逐项评审](judgments.json)、[分项统计](summary.json)、[离线审计](audit.json)和[候选绑定](review-candidates.json)可追溯。开发批次存在一次已披露的实现身份变化，见 [identity-deviation.json](development/identity-deviation.json)，不当作严格冻结对照。

24 条确认记录、两份报告的 6 个阶段、CPU 对话 4 轮均实际零生成、零模型元数据请求回放，并通过整个进程拒绝 HTTP 发送的[严格离线回放](network-free-replay.json)。失败的 CUDA 对话没有已完成轮次可回放，收据明确记录这一点。原 590 份冻结结果保持不变；344 份历史保护文件另由原验收入口核验。
