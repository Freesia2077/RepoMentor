2026-10-20。此前冻结的 [9B 对照](../qwen9b-reliability/report.md) 不重跑、不改写；本补丁仅处理该轮发现的对话目标传递与空白行编号缺陷。**四轮连续会话严格解决由 1/4 变为 2/4，已修复 off 追问答回 on 的复现案例。** 这是同一已知失败上的开发回归，不是新确认或泛化成绩。

## 修改

- “那么”后已明确写出 `off('FOO')` 等新调用时，不再拼接旧问题作为追问对象。
- 最终整理的 `question` 始终是当前用户问题；检索用的 `resolved_query` 放在独立导航字段，不能作为新的作答目标。真正有指代的追问仍保留导航与历史。
- 源码片段在渲染、合并、共享、裁剪及恢复时保留末尾空白行，确保记录的范围与实际编号内容一致；空白行不会变成额外事实。

SDK 继续执行循环，模型、CPU BM25 和预算均维持 9B/16K、研究 1536、最终 2048、200 行/8000 字节读取、12000 字节观察、36000 字节累计源码、6 请求/6 工具/360 秒。协议在补丁复测前冻结，参见 [protocol.json](protocol.json)。
