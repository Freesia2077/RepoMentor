来源核验得到三个具体观察：

- Nanoid：源码 `customAlphabet` 的显式 `defaultSize=2.9` 会进入闭包，随后 `size | 0` 得 2；0 和 -1 均不进入正数循环。保存 BM25 答案仍错用默认 21，说明有正确来源不保证条件理解正确。
- mitt 实现与测试：保存 BM25 答案完整说明原始 Map key、FOO/foo 与 Bar/bar；另存 SDK 最终答案只保留“不转小写”的核心结论。补查次数不能解释该完整性损失。
- mitt 四轮追问：CPU 演示流程完成，但第 2 轮引用没有覆盖大小写断言，第 3 轮正文声称删除 key，而源码实际是 `all!.set(type, [])`。引用路径与范围合法不代表语义支持。原 SDK 对话故障和阻塞轮次保留在原批次，不以这个 CPU 演示替换。

这些判断由 Agent 对照固定源码给出，不是新的模型生成正确率，`human_approved=false`，全部禁止训练。没有真人满意度、采用率或省时数据。
