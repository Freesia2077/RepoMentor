# SWE-QA：50题五组评测

2026-11-03。完成新增30题×5组生成，与上一轮修复后的20题×5组合并，共250个答案。新增249次本地生成请求，旧100个答案及评分按来源复用，没有挑选最佳尝试。本轮未改运行代码、提示或模型；373项离线测试通过，1项历史检查未选，Ruff通过。生成服务已停止。

**本样本中，检索总体优于闭卷，Agentic均分最高；代码增强没有超过普通BM25。Agentic收益伴随约4.5倍生成请求，且存在逐题退步。以下是模型辅助五维评分，不是准确率。**

## 方法与可比边界

数据固定为[SWE-QA作者数据](https://huggingface.co/datasets/swe-qa/SWE-QA-Benchmark/tree/f048f07da234b39e32937f115d027c5b71acd54e)，仓库SHA沿用[作者固定版本](https://github.com/peng-weihan/SWE-QA-Bench/tree/c13deac7a0d99b0ca2e593e004c4739475785b08)。四库源码均已下载为不可变快照，仅读取，不安装或运行目标仓库。新增题在生成前按种子20261103冻结，排除本地题库、旧90题及旧20题的规范化同文题；只做题干精确去重，没有语义去重或预训练污染证明。选择这四库是为了沿用已核验索引，覆盖原数据15库中的4库，不能声称全720题或跨新仓库泛化。

统一生成器为既有Qwen3.5-9B Q4_K_M，16K窗口、最终输出上限2048、temperature=0、seed=42、关闭思考。普通BM25与代码增强使用相同语法块和证据打包，后者增加符号、静态关系与角色排序。混合组复用BM25、归一化FAISS向量、RRF及Qwen3-Embedding/Reranker-0.6B。初始候选20、最多6个单元、源码8000字节；索引和向量缓存复用，没有新增检索实现。

Agent组初始原文与同题混合组完全相同，之后由OpenAI Agents SDK Runner自主补查，最多6次模型决策、6次仓库操作、360秒；研究轮输出最多1536 tokens，finalizer最多2048。评测显式选择混合检索；产品默认仍是代码增强BM25/CPU。Agent与单次生成在提示、导航和多轮预算上也不同，五组是完整流程比较，不能把全部差值单独归因于工具。闭卷只含题干、仓库名及允许使用已有知识的作答规则，没有源码或参考答案。

评分沿用[官方五维量表](https://github.com/peng-weihan/SWE-QA-Bench/blob/c13deac7a0d99b0ca2e593e004c4739475785b08/Benchmark%20construction/score/llm-as-a-judge.py)，由当前Codex会话对中文答案正文及英文参考进行模型辅助评审。新增评分时隐藏条件标签，但同一编排者能接触原始记录，属于部分遮蔽，不是独立盲评；没有人工批准，也不是论文GPT-5/Voyage-code-3配置复现。旧评分原样保留；新30题中同题同文的4份重复答案沿用首次评分。旧Streamlink-033两份相同正文原有30/31的一分评审差异保留，未事后调分。

生成前已标记4道主要参考问题：旧Pytest-023，以及新增Flask-020、Flask-030、Requests-035。回调不能保证并发Cookie写回一致性，accessed不决定Cookie序列化，无chardet分支不读取content。原题和参考不改，事实冲突以固定源码核查；主分母仍50。另行排除这4题的46题敏感性均分依次48.13、64.74、63.57、70.63、79.09；新增子集排除3题后的27题结果亦保存在[指标](metrics.json)，未换题或删除模型失败。

## 失败案例与反思

以下为事后挑选的具体源码复核，不是穷尽的错误分类统计。位置、原始输出和实际可见证据见[失败分析](failure-analysis.json)。

| 题目 | 观察 | 说明 |
| --- | --- | --- |
| Flask-042，定位URL测试类 | 两种BM25均35，混合及Agent均98 | BM25只给相关方法，漏TestUrlFor类声明；混合交付102–169完整类段。Agent没有调用仓库工具，这一例是初始证据改善。 |
| Streamlink-019，多继承测试工具 | 五组均未命中目标声明；Agent60 | _KickHLSStreamWriter已在原符号索引中，题干未给名字，实际请求却一直围绕通用HLS mixin。缺的是目标召回和搜索转向，不能说类不存在。 |
| Streamlink-027，文档插件发现 | BM25 76 → 代码增强39 | 实现角色先验将不相关实现放前，文档扩展片段仍可见却出现拒答。BM25本身也虚构了类名，不能算完整正确；不应把所有问题都优先当实现问答。 |
| Pytest-017，TestReadme职责 | BM25 90 → 代码增强59 | 两组含相同六段源码、顺序不同；增强组已见完整类，却先说不存在、后又准确描述它。属于证据利用和拒答校准失败，继续加模块不能解决。 |
| Pytest-013，参数校验 | 混合43，Agent79仍有遗漏 | 完整校验分支已可见，混合组仍颠倒默认参数条件；相邻get_default_arg_names未被交付。docstring称ValueError，执行链实际fail抛Failed，应追可执行分支。 |
| Flask-048，异常处理器遍历 | 混合88 → Agent67 | 两组初始均有完整方法；Agent额外3次仓库操作后，仍把命中即return说成必须遍历全MRO。更多调用没有带来更好的证据理解。 |
| Requests-035，编码探测回退 | BM25 88，闭卷39，Agent70 | BM25纠正参考的分支混淆；Agent虽给对utf-8，仍把两条content路径混为一谈。自动参考答案也需要源码核查。 |

另有Flask-040混合组、Pytest-010代码增强组正文提前结束。原始模型JSON本身已经闭合answer字段，finish_reason均为stop，分别输出312/154 tokens；客户端解析与原文一致，没有触及2048上限。两条均保留为“格式成功、答案不完整”，没有补写或重试。

176次Agent仓库操作中，31次被already_read拒绝、9次被duplicate_action拒绝，占22.7%。这些是有效的重复操作保护，但仍消耗决策预算；不应通过放宽重复读取或增加轮数掩盖搜索质量问题。

当前可支撑的结论是：在这50道公开源码问答及当前评分下，BM25相对闭卷提高16.82分，Agent相对BM25提高13.50分，同时需要4.5倍生成请求。代码增强没有独立正收益，混合重排也存在明显仓库差异。后续若继续改进，应先在已有选源器中处理类归属、文档角色及关键相邻分支，再检查已有证据的条件理解与停止判断；本轮到此结束，没有追加提示变体、检索模块或更多实验。这50题已曝光，仅作评测/开发记录，不进入后训练。
